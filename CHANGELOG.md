# Changelog

All notable changes to the Unified File Operations Platform are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Interface (WS-G, RcloneView parity)**:
  - **Guided wizards do the work** (palette *… (guided)* for all 18; `src/lib/guided-actions.ts`): 14 of the 18 only added an Activity line on Finish (and their *Test* buttons always passed). Now: sync pairs are created, SMB/SFTP connections saved, signed in and listed, transfers copy or move (with optional checksum verification), interrupted transfers resume, retry or cancel, file names are checked against a destination and renamed reversibly (new `compat_profiles`, `compat_scan_folder`, `compat_fix_names`, `compat_list_renames`, `compat_restore_names` over the compat engine and its mapping table), reports are saved, folders are offered to another computer, drives are copied after a space check (and verified), and backup jobs are created and run. Wizard errors keep the wizard open with the reason.
  - **App lock** (Settings → App Lock, palette and tray *Lock UFOP*; `app_lock_*`): lock at start, after 1–60 idle minutes (idle timer in the backend, fed by every window) or now; unlock with the master password (created when the lock is first turned on; attempt limit of the password manager). While locked the IPC gate (`app_lock::gate`) refuses every command except the lock screen's, and the web view holds its calls (identical ones once) until the unlock; scheduled work keeps running; audited.
  - **Several windows** (`open_new_window`; Ctrl/⌘+N, palette *New Window*, folder context menu *Open in New Window*, tray *New window*): each window has its own panes and tabs (`windowScopedStorage` keeps them out of the shared copy), shares favorites, recents, workspaces and settings, and follows changes made in the others (`storage` events, re-read on focus). Capabilities cover `win-*` windows; the portable data store applies to every window.
  - **Cloud folders in the sidebar** (`detect_cloud_folders`, `cloud_folders`): local folders synced by Dropbox (`info.json`, personal/business/team), OneDrive (`OneDrive*` variables, CloudStorage), Google Drive (CloudStorage `My Drive`, Windows drive letter), iCloud Drive, Box, pCloud, MEGA, Nextcloud/ownCloud (`localPath` entries of the client `.cfg`), Synology Drive and Proton Drive; existing folders only, each once.
  - **Reset settings** (Settings → Reset, palette *Reset Settings…*; `reset_settings`): appearance and layout, startup/tray/notifications, sync and transfer defaults, and the welcome tour, each optional, after a confirmation; only listed preference keys are removed (`reset::ResetScope::keys`) and the running app takes the defaults at once; data, saved passwords and integrations are kept; audited.
  - **Startup & Tray** (Settings; `get_startup_settings` / `set_startup_settings`): start at login (optionally in the tray), start minimised, minimise to the tray, close to the tray (the Backups screen's setting) and show/hide the tray icon; without a tray icon (hidden, or the desktop has none) nothing hides the window (`startup::effective`).
  - **Language** (Settings → Appearance and the onboarding welcome page): System default or one of the eight translations; the context menu, sidebar, Settings headings, navigation buttons, palette prompt and the tray menu (`set_ui_language`, `tray_labels`) follow it, `<html lang>` is set, and text without a translation falls back to English instead of showing the key.
  - **Accent colour** (Settings → Appearance): nine presets or any custom colour, applied to the design tokens and every `blue-*` utility through one generated stylesheet (OKLCH shades with Tailwind blue's lightness steps); high contrast is unchanged.
  - **Parent folder** button in the breadcrumb bar and shortcuts **Alt+↑**, **⌘↑** and **Backspace** (not while typing or while a dialog is open), plus *Go to Parent Folder* in the command palette; local paths and connection folders.
- **Folder compare and reconcile** (see `docs/user-guide.md` → *Folder Compare*): compare two folders — a local folder with another local folder or with a folder on a saved connection — recursively, with the sync filter engine (patterns, ordered rules, presets), size+time / size-only / checksum comparison and a depth limit, as a cancellable task with progress. Results show every entry as left only / right only / same / different / error with sizes, dates and reasons, folders rolled up from their contents, status chips with counts (OR filters), and in the Advanced view next-difference / largest-difference navigation and sorting by size difference. Tick entries (Shift for ranges) to copy them either way or delete them on one side: never copies entries that are already the same, goes through the Safety Interlock, the transfer queue (connections through their connectors), the Trash for local folders (not on Windows yet) and the ledger (new local copies are undoable; changes on a connection are not, and a copy that would overwrite files on a connection asks first), then re-compares only what changed. Remote entries are addressed by the paths their connection lists (Google Drive's item IDs), not by joined names. Safe by construction: everything inside a folder one side could not read is an error, names that are not plain (`..\..\x` from a server) can never be written outside the folder, an upload never overwrites a file that appeared on the connection after the comparison, folders whose contents were not compared are not "copied" as empty folders, and **Undo copies** also removes the folders made for the copies. Connector transfers in the transfer queue can be cancelled there (no Pause/Retry, which the queue cannot do for them). Opened from the pane toolbar (**Compare**), the command palette (*Compare Panes*, *Compare Folder With…*), the optional *Compare Folders* toolbar button and **Compare with…** in Connections. IPC `compare_folders`, `compare_cancel`, `compare_release`, `compare_plan_action`, `compare_apply` (event `compare-progress`).

- **Editable address bar**: click the breadcrumb (or Ctrl/⌘+L, palette *Go to Address…*) to type a local path, `conn://…` or `<connection name>:path`, with suggestions from the typed folder and recent places, and an inline error for addresses that do not exist.
- **Drag-and-drop semantics and confirmation**: same location ⇒ move (Alt ⇒ copy), across connections or between this computer and a connection ⇒ copy; *Settings › General › Ask before drag-and-drop copies or moves* (off by default) confirms first, showing the Safety Interlock's risk (the confirm button waits for that assessment, so a quick Enter never skips the interlock).
- Pane transfers are safer and steadier: folders copy correctly into Google Drive, at most 4 files run at once per connection, cancel, pause or a failure removes the partly written file, and a move out of Google Drive keeps the original document. A failed S3 server-side copy no longer deletes the only copy on rename, and the drag-and-drop confirmation counts every file a folder holds. Renaming a connection item (F2) onto a name already in its folder is refused, as on this computer, instead of replacing that item (SFTP, S3, rclone, ADLS and many FTP servers overwrite on rename), and deleting a connection folder is assessed by the Safety Interlock with every file it holds. Copies and moves treat names differing only by case as taken (Dropbox and case-insensitive SFTP/FTP servers would otherwise replace `a.txt` with `A.txt`); downloads check every file a folder holds (and export / keep-both names) against the filename policies before anything is created; a drop or cut+paste of an item into the folder it is in (also a Google shared-drive or Shared-with-me root) does nothing instead of renaming it to "(copy)"; a download never replaces a file saved at its destination meanwhile; a paused or cancelled server-side copy is waited for and removed, so a resumed job starts over; opened or previewed connection files are capped at 25 MB as they download (also when the listing gave no size) and the preview cache is pruned at startup (a week, 1 GB); opening a program or script from a connection asks first. Names a server or shared folder supplies (`..`, `/`, `\`, NUL; `:` on Windows) are refused before anything is planned, so a download can never land outside the chosen folder; every download stages in its own job-unique hidden file, so two transfers to one name never mix bytes (exactly one wins, the other is refused); a move within one connection is planned completely before any item is renamed on the server, and a failure after some renames names the items that already moved.

- **Sync (WS-C)** — see `docs/user-guide.md` › Sync:
  - **Two-way sync with a baseline**: two-way pairs record both sides after each clean run (schema v33 `sync_baseline_runs` / `sync_baseline`) and the planner does a three-way diff, so deletions propagate (rollback copies on either side) instead of coming back, changes flow both ways, edits on both sides are conflicts, and the first run still never deletes. Failed, cancelled or paused runs keep the old baseline. Safety stop (`copy_options.two_way_max_delete_percent`, default 50%) when a side lost most of its files or is empty/missing. IPC `get_sync_baseline_info`, `reset_sync_baseline`; Advanced *Reset history*.
  - **Compare files by** size and date, checksum (xxHash3, with a preview note when no hash is available) or size only (`copy_options.compare_mode`); Advanced **Ignore existing** preset (/XO /XN /XC).
  - **Versioned backup**: a version index at the destination (`.ufop-sync-versions.json`) and `run_options.keep_versions` pruning (retention keep-count), shown as *versions removed* in the report.
  - **Crash recovery**: finished steps are checkpointed per run; a rerun after a crash or cancel skips them (`report.resumed`).
  - **One filter engine** (`ufop_core::filter_rules`) for sync and backup: ordered rules with rclone globs, `--filter-from` import (`parse_filter_rules`), new groups images/video/audio/documents/archives (`get_filter_groups`, also as sync quick presets), and user-saved presets (schema v33 `user_filter_presets`; `list_user_filter_presets`, `save_user_filter_preset`, `delete_user_filter_preset`) in both editors.
  - **Edit and duplicate**: pairs open in the create form for editing (trigger changes apply at once); `duplicate_sync_pair` and `duplicate_backup_job` copy a definition as "*name* (copy)" with no history and schedules off (a scheduled or watched sync pair's copy keeps its trigger and starts disabled, turned on from Edit; backup copies take the schedule and maintenance their templates gave the original as their own, turned off, turn replica timers off and get their own copies of stored credentials, keeping references to secrets this machine does not store).
  - **Export / import one pair** (`export_sync_pair`, `import_sync_pair`; `{"format":"ufop-sync-pair","version":1}`), flagging missing folders and saved connections.
  - **Global sync defaults** (`get_sync_default_options`, `set_sync_default_options`; Settings › Advanced): new pairs store only their own options (`option_overrides`); older pairs are unchanged.
  - **Bandwidth timetable** (`get_bandwidth_schedule`, `set_bandwidth_schedule`; Settings › Advanced) on the one shared limiter (`ufop_core::throttle`): while a window is active its upload limit covers file transfers, sync copies and backups together (download limit: backup restores) and replaces the backup machine-wide limits (a window's 0 keeps the machine-wide limit for that direction). Outside windows the backup machine-wide limits still pace backups only, as before.
  - Two-way pairs with *Blind upload* never delete: the destination is not read, so no baseline is used or recorded.
  - Crash-recovery checkpoints record the pair's folders and mode and are dropped when the pair is edited or deleted; a step is skipped only while its result is still in place, and versions stored before a crash are added to the version index on resume.
  - `planner::diff_trees`: the planner's decisions on two listings, pure and cancellable, for folder comparisons.
  - Sync filter rules match folders like backup does: folder rules and the groups' folder entries (`*/tmp/`, `*/node_modules/`, `cache/`) exclude everything inside, and `*/Thumbs.db`-style entries match at the pair's top folder.
  - Two-way: a file changed on both sides to the same bytes (e.g. copied by a failed run without kept timestamps) is settled by content hash instead of becoming a conflict.
  - rclone rules (imported `--filter-from` files) in a backup job match paths inside each source folder, so `/Photos/**` is the source's own `Photos` folder rather than one at the filesystem root; as in rclone, a file pattern such as `- *` no longer hides folders (`+ *.jpg` / `- *` keeps JPEGs at any depth) in sync pairs and backup jobs.
  - Two-way pairs set to *Trust the inventory* scan the destination every run (with a preview note and a hint in the editor): the saved inventory cannot show changes made there, which let a source deletion remove an edited destination copy.
  - Versioned backup destinations written before the version index (numbered `name.vN.ext` files, no `.ufop-sync-versions.json`) are adopted on the first run: their versions count for `keep_versions`, /PURGE leaves them alone, numbering continues and unchanged files are not stored again. Templates whose names depend on dates or other tokens than the name, extension and number cannot be recognised; such files stay as they were.
  - Editing a watched pair whose folder cannot be watched saves the edit (the watcher failure is logged, as when a pair is created) instead of failing after the pair was changed in memory; a resumed run's checkpoint no longer glues its first step onto a line torn by a crash.
  - Editing a pair with an invalid schedule is rejected before anything changes.
  - Security: `keep_versions` pruning only deletes version files inside the destination. Entries of `.ufop-sync-versions.json` (which anyone who can write the destination can edit) whose path is absolute, contains `..`, or leads through a folder symlink out of the destination are ignored, reported in the run's errors and dropped from the index; their files are left alone.
  - A backup job's generated CLI command writes rclone rules as `--filter "+ pattern"` (new `ufop backup run` / `estimate` flag, applied in order after `--include` / `--exclude`) instead of an absolute-path regex, so it selects the same files as the job (`/Photos/**` is the source's own Photos folder).
  - Settings › Sync defaults shows every mode's cleanup default, including the two-way delete limit (it was edited as a one-way pair, so that limit could not be set there).
  - Sync copies are paced block by block whenever the bandwidth timetable has an upload limit, so a window that opens during a long copy slows the rest of that file.
  - Standard view: a sync pair's filter rules (e.g. from an applied preset) are listed read-only with remove and *Clear all rules*, so a preset can be undone without the Advanced rule editor.
  - Importing a scheduled or watched pair leaves it turned off (with a note to turn it on in Edit), like a duplicate, so it cannot start running before it is reviewed.
  - Two-way: each copied file's history entry comes from that step (the origin as planned, the copy read right after it was written) instead of a reading of both sides at the end of the run, so a file edited while the run was going is copied next time instead of being overwritten by the older copy or never sent. Links copied as links are recorded as the walk lists them, so they no longer read as changed every run.
  - Two-way: Rollback also forgets the restored files' sync history and puts back their original modification time, so the next run treats a restored file that differs from the other side as a conflict (pair's policy) instead of copying it over the other side's newer version.
  - Two-way: folders deleted on one side are removed on the other once the run has deleted their files there (folders that still hold other files, or that the first side still has, stay).
  - Two-way with /MOV (move files): a file moved to the destination leaves the sync history, so the next run no longer reads its missing source copy as a deletion and deletes the destination copy, the only one left (it is copied back to the source, as before two-way history).
  - Two-way: after a run with errors (which keeps the previous history) the preview notes that deletions since the last clean run are not tracked yet.
  - Rule files (`--filter-from` style) whose lines start with a non-ASCII character (an en or em dash pasted from a web page) are rejected with the usual "must start with + or -" message instead of crashing the import or `ufop backup run --filter`; a leading UTF-8 byte order mark is ignored.
  - Bandwidth timetable: a window's 0 for a direction keeps the backup machine-wide limit for that direction (a download-only window no longer lifts the upload cap).
  - Editing a layered sync pair keeps its earlier option overrides, including ones whose value equals the current default; setting an overridden option to the default in the form resets it to follow the defaults.
  - Versioned backup: a newest stored version whose file was removed from the destination no longer counts as stored; the file is stored again.
  - Importing a sync pair refuses unknown option names in `option_overrides`, as creating and editing do.
  - Two-way: names that differ only in letter case between the two sides (a case-only rename such as `A.txt` to `a.txt`) are skipped with a reason and a preview note, and their history is forgotten, instead of being planned as an add plus a delete, which on a case-insensitive drive (macOS, Windows) deleted the file on one side and, on the next run, on the other. Deletes also check that the folder lists the file under exactly the planned name.
  - Rollback is refused while the pair is syncing (and holds the pair so no run starts during it); the Rollback button is disabled during a run.
  - Bandwidth timetable: each direction takes the first active window that limits it, so a download-only window listed first no longer hides an overlapping window's upload limit.
  - Two-way pairs refuse Move files (/MOV, /MOVE) on create, edit and import (moved files were copied back on the next run), do not inherit it from the global defaults, and no longer offer it in the options; older pairs saved with it get a preview note.

### Fixed

- Automation *Purge* step: only the target folder itself was checked for being a link; a linked folder among its parents led the purge elsewhere (another drive, the home folder) and deleted that. A path through a linked folder (below the top level) is refused, the home-folder check also judges the real location, and exactly that folder is removed.
- Signing in to Google Drive, Dropbox or OneDrive: the new tokens were stored only after connecting with them worked, so a network error at that moment discarded them (and the one-time code), and you had to sign in again. They are now kept on any error other than a refused credential, and the sign-in says the service could not be reached yet.
- Security: on macOS and Windows the SMB password was on the mount command line (`mount_smbfs` URL, `net use /password:`), visible to every user in the process list. macOS now mounts through NetFS and Windows connects through `WNetAddConnection2` (to the UNC path; the old code also picked the drive letter from the temporary mount folder's first character), with the password as an API argument; Linux keeps passing it to `mount.cifs` in the environment.
- Two-way sync (and any delete step) removed a file that was edited after the run was planned, edit included. A delete now goes ahead only while the file has the size and modification time the plan saw; otherwise it is kept, reported, and synced as an edited file next run.
- Address bar: a local path containing `:` (`/home/me/notes:2024`, `/Volumes/Backup 10:30`) was read as a remote address and rejected. Absolute local paths are now recognised first.
- The risky-file warning missed Windows types that run code when opened (`.lnk`, `.scf`, `.hta`, `.cpl`, `.msc`, `.reg`, `.vbe`, `.jse`, `.wsf`, `.wsh`, macro-enabled Office files and disk images) and names hiding the type behind trailing dots or spaces (`setup.exe.`).
- Log viewer live tail: when more lines arrived between two refreshes than one page holds, the older ones were never shown. The tail now pages forward until it has caught up (up to 20 pages) and says so when it could not.
- An interrupted move to or from a cloud came back after a restart as a copy, leaving the originals in place. Moves in flight are saved with the queue and the restored jobs finish them; a move whose jobs are gone keeps its originals.
- Folder compare: removing a folder found empty could take along a file saved into it in the meantime. Local folders are now removed with an atomic "remove only if empty".
- The window `Destroyed` handler stopped backups and saved the queue whenever any window closed; with several windows it now runs only when the last one closes, and the tray's *Backups…* opens the Backups screen in the first window only.
- Choosing English on a computer set to another language did not stick: English counted as "no choice", so the computer's language came back at the next start. The choice is now stored as such (persisted state v1; an older non-English choice is kept).
- The parent of a Windows folder directly on a drive (`C:\Users`) was `C:` (that drive's current folder) instead of `C:\`, and the parent of OneDrive's root (`/drive/root:`) was `/drive`, which cannot be listed; both now stop at the root.

- Moving a file to the Trash on Linux overwrote a file of the same name already in the Trash, and on macOS two files of the same name trashed within one second did; the second one now gets a number (`notes 2.txt`) on both.
- Undoing a "create folder" operation that created nested folders could fail with "Directory not empty" (the parent was removed before the folder inside it); folders are now removed deepest first.
- **Vaults no longer claim Cryptomator compatibility**: the module docs said Cryptomator v8 vaults were supported, but no such code exists; they now describe the format actually used, and the vault form's "Cryptomator compatible" checkbox (which changed nothing) is gone. Existing vault files with the flag still load.

- **Rejected credentials are no longer retried**: 401/403 and refused sign-ins are `AppError::Authentication` (not retried by the shared retry policy, `ufop_core::retry::is_retryable`); the connection is flagged *Credentials rejected*, and backups, automation and auto-mount skip it until it is edited or *Retry* is clicked. Backup destinations used to retry a 401 with backoff. An SMB share refusing the user name or password counts too (connect and mounts); a Google Drive 403 for a rate limit or quota is retried later, not flagged, by the connector and by Google Drive backup destinations alike (one shared reason check). Share links (a user action) still try a flagged connection.
- Backblaze B2 connected with an empty application key (every connection failed) and could deadlock re-authorizing an expired token.
- Connecting a saved connection ignored its connector settings; the SFTP key passphrase, WebDAV bearer/vendor settings and SMB domain (and password) never reached the connectors.
- Google Drive listings stopped after 100 items and folder paths below the top level did not open; OneDrive paths below the root did not open; the cloud trash/permanent-delete commands used a connector that was never signed in.
- **Two-way sync deletions never stuck**: a file deleted on one side was copied back from the other on the next run.
- **Versioned backups stored a duplicate version of every file on every run** (copies were never seen as already stored).
- **The transfer bandwidth limit was never applied**: `set_global_throttle` stored a limit no transfer obeyed; chunks are now paced.
- **Sync resume was dead code**: the resume state was read but never written; replaced by real checkpoints.
- **rclone backup destinations**: when rclone failed before reading the data sent to it (quota exceeded, permission denied), the error said "Broken pipe" instead of rclone's own message.

Each `Migration { version, description, sql }` entry in `all_migrations()` is now validated: non-empty `description`; `sql:` field must reference a constant named exactly `V<version>_SCHEMA` (codifies the naming convention so a copy-paste bug like `version: 12, sql: V11_SCHEMA` is caught); the referenced constant must exist; its body must contain at least one DDL/DML/PRAGMA keyword (empty stubs silently no-op at runtime → schema drift); each `V*_SCHEMA` constant must be referenced exactly twice in the file (definition + one use — orphan constants and accidental re-use both fail). - Extended `scripts/check-migrations.sh` again with a **destructive-DDL safety check**. Default-deny: unjustified destructive DDL fails the gate. Data loss via an unconsidered schema migration is the single most catastrophic failure mode for the storage layer; this forces a written justification at write-time. - New verify-gate stage `invoke-types` (`scripts/check-tauri-invoke-types.sh`, `pnpm invoke-types:check`) fails the gate when a `tauriInvoke(…)` (or `tauriInvokeSafe(…)`) call's return is **consumed** (assigned, returned, used in expression / arg / ternary) without an explicit `<T>` type argument. Statement-form `await tauriInvoke("delete_X", { … })` calls (return discarded) remain legitimately untyped. The IPC boundary is the desktop app's most type-fragile surface; without `<T>` TypeScript infers `unknown` and downstream `.field` access yields runtime `undefined` while compiling cleanly. Categorization walks back through whitespace + optional `await` to inspect the preceding token (`=`, `(`, `,`, `?`, `:`, or the `return` keyword = consumed). Sub-second on ~320 call sites.
- Extended `scripts/check-command-return-types.sh` (iter 30) with **parameter snake_case discipline**. Each `#[tauri::command]` parameter name must be snake_case. Rust's built-in `non_snake_case` lint warns on the same shape, but it can be locally disabled with `#[allow(non_snake_case)]`; this gate stage defends against that. A camelCase Rust parameter would serialize into the JSON wire format as `someParam` (Tauri uses Rust identifiers verbatim) — leaking the implementation naming into the IPC contract. Awk param-scanner skips `self`, `&`-prefixed references, and `mut` prefix; tracks `<>`/`()` nesting depth so `State<App, MyState>` is not mis-split on its inner comma. All 359 commands today pass — pure regression-prevention.
- Refined iter 32's V*_SCHEMA reference count in `scripts/check-migrations.sh` to be **comment-aware**. Line-comments (`// …`, `/// …`, `//! …`) and block-comments (`/* … */`) are now stripped before counting `V*_SCHEMA` tokens, so a future `// historical note: V11_SCHEMA used to also cover the ledger shape` does not inflate the per-constant reference count and trigger a false-positive "re-use" failure. Today's codebase has zero such comments so no behaviour change; this closes the documented iter-32 false-positive risk.
